## Users Module

### Base CRUD

| Method | Endpoint    | Description              |
| ------ | ----------- | ------------------------ |
| POST   | /users      | Create user              |
| GET    | /users      | Get users (with filters) |
| GET    | /users/{id} | Get user by ID           |
| PATCH  | /users/{id} | Update user              |
| DELETE | /users/{id} | Soft delete user         |

### Filters

```
GET /users?email=abc
GET /users?username=john
GET /users?status=active
GET /users?verified=true
GET /users?role=admin
GET /users?created_at=gte:2026-05-01
```

### Special Actions

| Method | Endpoint               | Description     |
| ------ | ---------------------- | --------------- |
| PATCH  | /users/{id}/activate   | Activate user   |
| PATCH  | /users/{id}/deactivate | Deactivate user |
| PATCH  | /users/{id}/restore    | Restore user    |

## Query Standard

### Filtering

```
?field=value
?field=gt:10
?field=lt:100
?field=gte:2026-01-01
?field=lte:2026-12-31
```

### Search

```
?search=keyword
```

### Sorting

```
?sort=created_at&order=desc
```

### Pagination

```
?page=1&limit=10
```

## Response Format

```json
{
  "success": true,
  "data": {},
  "meta": {
    "page": 1,
    "limit": 10,
    "total": 100
  },
  "error": null
}
```

---

## Guidelines

- Do NOT create one API per scenario
- Use filters instead of multiple endpoints
- Separate analytics from CRUD
- Keep response structure consistent
- Avoid exposing DB schema directly

---

## Mental Model

```
RESOURCE → OPERATIONS → FILTERS → RELATIONS → ANALYTICS
```
