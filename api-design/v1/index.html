    API Reference v1¶

    This page lists every HTTP route in the TestFlow backend. Use it to find an endpoint fast. For how a feature works end to end, follow the link at the top of each section.

    There are 178 routes in 40 controllers.

    Conventions¶

    Base URL and versioning¶

    • There is no global prefix and no Nest versioning. Each controller puts v1/ in its own path, for example @Controller('v1/assessments').
    • So almost every route starts with /v1/....
    • Three routes have no v1: GET /ping, GET /health, and POST /webhooks/razorpay.
    • The server listens on PORT (default 3000). CORS is open to any origin, with credentials.

    Authentication¶

    Every route needs a valid access token unless it is marked @Public(). Send the token in the Authorization header:

    GET /v1/auth/me
Authorization: Bearer <accessToken>
    • You get tokens from POST /v1/auth/login, /signup, /google, or /refresh.
    • Public routes need no header. If you send a token to a public route, it is ignored. The route does not know who you are.
    • A missing or bad token returns 401.

    The global guards run in this order on every request:

    1. JwtAuthGuard checks the Bearer token (skipped on @Public() routes).
    2. RateLimitGuard applies the @RateLimit() policy, if the route has one.
    3. RolesGuard checks @Roles(). Only one route uses it.
    4. OrgContextGuard loads the organization for org routes.
    5. PermissionGuard checks @Permissions() and @OrgPermissions().

    What the "Auth" column means¶

    Value Meaning
    Public No token needed.
    JWT Any logged-in user. The service may still check ownership (for example, "only the creator can edit").
    Perm x:y Logged-in user whose platform role grants permission x:y. Missing permission returns 403 Missing permission: x:y.
    Org perm x:y Route acts inside an organization. The caller must be an active member, and their org role must grant x:y.
    Org header Route accepts the optional x-organization-id header. See below.
    Role super_admin Caller must have the super_admin platform role.
    AI cost N Uses the shared AI generation rate-limit bucket. See Rate limits.

    See RBAC for roles and permission keys.

    Organization context¶

    There are two ways a route can act inside an organization.

    1. Path-scoped routes (@OrgScoped())

    The org uid is in the path: /v1/orgs/:orgUid/....

    • The caller must be an active member of that org.
    • @Permissions() on these routes is checked against the caller's org role, not their platform roles.
    • If the caller is not a member, the API returns 404 Organization not found. It does not return 403, so it does not reveal that the org exists.

    2. Header-scoped routes (@OrgHeaderScoped())

    Send the org uid in a header:

    x-organization-id: org_8f3k2l
    • The header is optional.
    • Without the header, the request runs in your personal scope. @OrgPermissions() is not checked. A plain @Permissions() is checked against your platform roles.
    • With the header, you must be an active member (else 404). Both @Permissions() and @OrgPermissions() are checked against your org role.

    See Organizations.

    Success envelope¶

    Every successful response (except 204) uses ApiResponse:

    {
  "success": true,
  "message": "Assessments fetched successfully.",
  "data": [ { "id": 12, "title": "JavaScript Basics" } ],
  "meta": { "total": 42, "page": 1, "limit": 20, "totalPages": 3 }
}
    • message is always present.
    • data is always present. It is null when there is nothing to return.
    • meta is only present on list endpoints (and a few others, like the leaderboard).
    • 204 No Content responses have no body.

    Error envelope¶

    All errors go through HttpExceptionFilter:

    {
  "success": false,
  "message": "Missing permission: questions:create"
}
    • There is no nested error object and no statusCode field. Use the HTTP status code.
    • If the thrown exception carries extra fields, they are added at the top level. For example, GET /health returns data with its 503.
    • Any unexpected error returns 500 with "message": "Internal server error". The details are only logged on the server.
    • Business-rule errors from the domain layer are mapped to 409, 400, 403, or 422.

    Common status codes:

    Code When
    200 OK
    201 Created
    202 Accepted. Work was queued. Poll the returned job id with GET /v1/jobs/:id.
    204 Done, no body (most deletes)
    400 Validation failed, or a bad request
    401 Missing, invalid, or expired token
    403 Missing permission or role, or not the owner
    404 Not found, or not a member of the org
    409 Conflict (duplicate, wrong state)
    422 Business rule broken
    429 Rate limit hit
    503 A dependency is down, or a job could not be queued

    Validation errors¶

    The global ValidationPipe runs with whitelist, forbidNonWhitelisted, and transform turned on.

    • Unknown fields in the body or query are rejected with 400. They are not silently dropped.
    • Query strings are converted to the right type (numbers, booleans).
    • All validation messages are joined into one string with ,:
    {
  "success": false,
  "message": "email must be a valid email address, password must be at least 8 characters"
}

    Path ids that must be numbers or UUIDs (ParseIntPipe, ParseUUIDPipe) also return 400 when wrong.

    Pagination¶

    There are two styles. Each list endpoint uses one of them.

    Page style (most lists, including most admin lists):

    ?page=1&limit=20
    • page starts at 1. limit defaults to 20 and is usually capped at 100.
    • meta looks like { "total": 42, "page": 1, "limit": 20, "totalPages": 3 }.

    Cursor style (lists built on PaginationDto: invited assessments, participants, leaderboard, conversation messages, roadmaps, roadmap templates, org members, admin users, admin organizations):

    ?cursor=7&limit=20
    • cursor is the id of the last item from the previous page. Leave it out for the first page.
    • limit defaults to 20, max 50.
    • meta looks like { "nextCursor": "7", "total": 42 }. nextCursor: null means this was the last page.
    • Some endpoints add more to meta. The leaderboard adds me. Participants adds counts.

    Many lists also take search, sort, and order (asc or desc). The tables below list the main ones.

    Rate limits¶

    Routes are only limited when they have @RateLimit(). A method-level policy replaces the class-level one.

    Tier Limit Keyed by Used for
    Class A 10 per 5 minutes IP Auth routes
    Class B 30 per minute User (IP if not logged in) Writes: create, update, submit, enrol
    Class C 120 per minute User (IP if not logged in) Reads, lists, polling
    AI generation Class B bucket, scope AI_GENERATION, each call costs 3 or 5 tokens User AI generation routes
    • Routes with the same scope share one bucket. All AI generation routes share the AI_GENERATION bucket. At cost 5, that is about 6 calls per minute.
    • Every limited response has X-RateLimit-Limit and X-RateLimit-Remaining headers.
    • When you hit the limit, you get 429 with a Retry-After header (seconds):
    {
  "success": false,
  "message": "Rate limit exceeded. Please retry later."
}

    Swagger¶

    • Interactive docs are at /api/docs.
    • The page is protected with HTTP Basic auth. The username and password come from SWAGGER_USER and SWAGGER_PASS.
    • Click Authorize and paste an access token to call protected routes. The token is kept across reloads.
    • The Razorpay webhook is hidden from Swagger.

    Webhooks and raw body¶

    • The app is created with rawBody: true, so req.rawBody holds the exact bytes sent.
    • POST /webhooks/razorpay uses the raw body to check the x-razorpay-signature HMAC. A missing or wrong signature returns 401.
    • See Commerce.

    Next-assessment suggestion¶

    POST /v1/attempts/:attemptUid/next-assessment returns the suggestion as data. GET /v1/attempts/:attemptUid/result returns the same object as data.nextAssessmentSuggestion, or null when none has been made. Clients show a "suggest" button when it is null.

    {
  "name": "SQL Joins — Focused Practice",
  "title": "SQL Joins Practice",
  "description": "Practises the outer joins you missed most, at a gentler difficulty.",
  "prompt": "SQL joins at an intermediate level, focusing on LEFT and FULL OUTER JOIN semantics.",
  "duration": 20,
  "maxTotalQuestions": 10,
  "sections": [
    {
      "title": "Outer joins",
      "prompt": "LEFT and FULL OUTER JOIN results on small tables; ask what rows come back.",
      "questionType": "mcq",
      "questionCount": 10,
      "difficulty": 2,
      "positiveMark": 4,
      "negativeMark": 1
    }
  ],
  "generatedAt": "2026-10-28T09:00:00.000Z"
}

    It is the start-ready part of an assessment template (no uid, slug, owner or visibility). To start it, send it as a manual-mode POST /v1/assessments/generate: mode: "manual", title, prompt, duration and the sections. That spends AI_ASSESSMENT as usual.

    Status When
    400 Attempt uid malformed, or the attempt is not evaluated yet.
    403 Not your attempt, or your plan does not include AI_ASSESSMENT_SUGGESTION.
    404 Attempt not found.
    409 The attempt was rejected by a reviewer.
    503 The model call failed after its repair attempts.
